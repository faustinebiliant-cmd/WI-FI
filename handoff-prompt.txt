## 1. PROJECT OVERVIEW
We are building **OSWAGOTech WiFi**, a multi-tenant hotspot billing SaaS for hotels and guest houses in Tanzania. 
- **Business Model:** Voucher-based. Guests buy a paper code at reception, enter it on a captive portal, and get WiFi for a set time and speed.
- **Market:** Tanzania (TZ). Timezone is strictly EAT (UTC+3).
- **Stack:** Node.js/Express + Supabase (Postgres) backend. React 18 + Vite frontend. No TypeScript. No ORMs. Raw SQL and PL/pgSQL.

## 2. THE ARCHITECTURE (NEVER BREAK THESE RULES)
- **3 Frontends:**
  1. Portal (`localhost:3000`): Guest facing. No login. Redeems vouchers.
  2. Tenant Panel (`localhost:3001`): Hotel owner facing. Manages packages, routers, vouchers, sessions.
  3. Platform Panel (`localhost:3002`): You (SaaS owner). Manages tenants, monitors hardware, impersonates tenants.
- **1 Backend:** (`localhost:5001`). 
- **The Router Adapter:** We never talk directly to hardware. We use `services/routers/routerFactory.js` which returns `MockRouter.js` (currently) or `MikroTikRouter.js` (future).
- **Security:**
  - Two JWT secrets (`JWT_SECRET` for tenants, `ADMIN_JWT_SECRET` for platform). They must be 32+ chars and never equal. `config/env.js` enforces this on boot.
  - Passwords are hashed with bcrypt. Router API passwords are encrypted with AES-256-GCM in `utils/encryption.js`.
  - Strict input validation via `utils/validators.js`.
  - `tenant_id` is ALWAYS extracted from the JWT, NEVER from the request body.
- **Data Format:** Speed is stored in Kbps. Duration is stored in minutes. The UI accepts Mbps/Hours and converts them.
